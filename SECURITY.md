# Security

This guard is defense in depth, not a certified safety system. Physical emergency stop, SDK motor limits, access control, and owner supervision are independent requirements. An app must call the guard before execution and fail closed on errors. Observing a transcript after realtime audio has been queued does not guard that speech; wrapping an already-running tool path does not guard its effects. This package does not integrate with the Conversation App; it owns a separate proposal/output path. The optional SDK motion adapter uses version-pinned task and stop protocol methods, but its limits and cancellation timing have not been validated on hardware. Do not enable it around people without a live safety review. Untrusted text must remain data, never instructions. Do not log secrets, transcripts, or images. Report vulnerabilities through GitHub's private vulnerability reporting feature.

The action guard holds uncertain audience, privacy, hostile-tone, request-match, and motion-safety judgments rather than approving them. It blocks only at configured high-score or clear-negative bands. The numeric answers still come from a fallible model; these code thresholds do not establish calibrated confidence, reliable detection, or physical safety. A model request and its local verdict use the same policy snapshot so an edit during the request cannot silently reinterpret its answers.

The owned voice host also requires a confident Jev Choice route after an inbound approval. An `ignore` route drops the turn; a `llm` route can only reach the proposal-only planner; a `fast_path` `stop` requests owned output stop. Missing, conflicting, or unsupported fast commands hold rather than reaching a robot sink. Exact local hard stops bypass the model. Choice confidence is not calibrated, and the route recorded in the ledger is only model evidence, not proof of a command or physical stop. The half-duplex host still cannot detect a spoken stop while the speaker is playing; keep a separate physical stop.

`conscience-voice` requires an interactive operator and a separate hardware acknowledgement flag. It loads policy between turns, keeps motion and all tools disabled by default, and does not automatically reopen the microphone because the SDK has no playback-complete acknowledgement. `--enable-local-notes` registers only a private file append tool; the effective guard policy always requires confirmation for it, and an independent exact-argument browser approval is mandatory before dispatch. This opt-in does not enable external messages or motion. The operator must wait until the speaker is quiet before pressing Enter. Ctrl+C or `q` requests owned audio and motion stop, but the request is not a physical emergency stop and may race with queued output. The console token is printed to the private terminal; keep it away from the planner and untrusted people. This host has not been run on hardware, so use requires an independent operator and physical-stop procedure.

`OwnedPlaybackGate` in the voice host arms the SDK speaker only at the approved speech sink, not merely after receiving a transcript. A stop revokes future enqueues and requests another halt if an in-flight arm or enqueue finishes after the first halt. These are software ordering guarantees with fake ports, not proof that the robot fell silent in time. `ReachyMediaAudio.halt_audio()` requests the pinned backend's queue flush before stopping playback. Missing flush support prevents playback arming, and a flush exception leaves the adapter disarmed while still requesting `stop_playing()`. The WebRTC backend may swallow a daemon-clear failure into its own log; no API acknowledgement proves the speaker queue is empty. This software gate cannot be represented as a verified hardware emergency stop.

The optional microphone ingress buffers at most a bounded utterance in memory and stops capture before ASR. Its energy delimiter can miss quiet speech, split a command, or mistake noise for speech; it is not an emergency-stop detector. A stalled backend read may delay capture shutdown, and ASR can mis-transcribe a spoken stop. Keep a physical stop independent of this path. The local faster-whisper adapter requires explicit model assets and does not intentionally upload audio, but replacement ASR, planner, guard, or TTS adapters can have different data flows. Review and disclose those flows before processing real voices.

The local Ollama planner accepts only numeric loopback HTTP endpoints and does not follow redirects or environment proxies. Its JSON schema is not a security control: it validates the complete response and passes every typed proposal through the inbound/action guard before any owned sink. Ollama model installation, the Jev guard request, and any third-party replacement adapter have separate privacy and supply-chain implications. The eSpeak/FFmpeg fallback does not play sound itself; its subprocesses receive only text after approval and return bounded PCM. No supported configuration should expose the robot audio, motion, or effectful-tool handles to a planner.

The ledger stores generic action-kind summaries by default and exports no summary unless explicitly requested. Its top-three numeric judgments and reason codes can still reveal behavior patterns, so protect the SQLite file and exported JSONL. `store_summaries=True` retains caller-provided text and requires an informed operator decision. Migration preserves old database rows; it does not wipe summaries that older versions wrote. Policy JSON is atomically replaced with owner-only permissions, but the host must also secure its directory and authenticate any future settings UI. The five-case dry run and 20-case synthetic red-team run never dispatch actions; a real guard adapter can still make network requests. The red-team corpus contains authored prompts and intent labels, not consented real sessions or verified safety labels. Do not treat its verdict counts or p95 as a confusion matrix or deployment performance.

The standalone owner console binds only to numeric loopback, requires a high-entropy bearer token for all policy and ledger APIs, rejects unexpected Host and cross-origin write requests, uses no authentication cookies, and sets a restrictive CSP. The browser holds the token only in memory. Its CLI requires an owner-only state directory, but other local processes under the same account, browser extensions, terminal history or recording, and a compromised host can still read the token or files. It is not a remote administration service. The optional TypeSafe preview and synthetic red-team run are explicitly enabled and confirmed, may be billable, and send policy and synthetic actions to the configured guard; they cannot dispatch robot outputs. Never proxy or tunnel the console to another machine.

An integrating host can opt into the exact-argument owner-approval broker and expose its pending request through this console. The broker has no tool-output handle and allows only one pending request with a short deadline. Its HTTP decision endpoint requires the same bearer token and binds a one-shot ID plus digest; it rejects stale or mismatched requests. A hard stop or console shutdown cancels pending approval. This is only as strong as the local token and the host's separation of planner, approval, and tool-dispatch ports. Any local process or browser extension with the token can impersonate the owner; an approved request may still fail to execute, and a tool may have effects outside this broker's knowledge. Do not enable effectful tools on a robot without operator review, hardware testing, and an independent physical stop.

The optional `LocalNotesTool` is an example of a real effectful sink, not a default-enabled robot capability. Its path is fixed by the host and its append is restricted to an owner-only directory and regular owner-only file. It stores exact approved text locally, so the file itself may contain sensitive information and must not be published or synchronized inadvertently. The file cap, no-follow checks, and local locking limit common mistakes; they do not protect against a compromised same-user process or provide rollback after a write. The host registers it as effectful only with `--enable-local-notes` and keeps the broker, console token, and output handle away from the planner. A pending approval times out after 10 seconds; denying or timing out leaves the file untouched.
